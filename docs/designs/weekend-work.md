# 주말근무 신청 앱 변경 계약

## 대상과 보존

- 환경 `DEX_CRM_LIVE`, 기존 Canvas 앱 `8cbb6cab-e76f-4278-af40-6670d5a29816`, 비관리형 솔루션 `LSW_WeekendWork`.
- 휴가 사본의 원본 `cr288_tb_employee`, `cr288_tb_adminpassword`는 읽기 전용으로 유지한다.
- 새 직원·관리자 테이블은 원본 업무 열 구조와 행을 복제한다. 새 관리자 테이블의 비밀번호 열에는 Dataverse 열 보안을 적용한다. 비밀번호 값은 Dataverse에만 저장하며 앱 데이터 원본과 Git에는 넣지 않는다.

## 신청 데이터

- 신청은 새 `lsw_tb_weekendworkrequest`에 저장하고 신청자 Lookup은 새 `lsw_tb_employee_weekendwork`를 가리킨다.
- 예정과 완료 신청은 `lsw_requesttype`으로 구분한다. 완료 신청이 예정 신청과 연결되면 `lsw_plannedrequest` Lookup에 기록한다.
- 앱은 신청자·승인 관련 열과 직원 Lookup을 채우지 않고 신청 행을 생성한다. 승인 Flow가 Dataverse `createdby` 사용자 이메일로 복제 직원 행을 하나만 확인한 뒤 신청자 정보·Lookup을 채우고 `Pending`, 현재 단계 1로 초기화한다. 직원 행이 없거나 중복이면 `RoutingError`로 종료한다.
- 승인 결과는 `Pending`, `Approved`, `Rejected`, `RoutingError`와 단계별 결과 열에 저장한다. 경로를 찾지 못하면 승인 요청을 보내지 않고 `RoutingError`로 남긴다.

## 화면

- 예정·완료 신청: 입력값과 근무 시간을 검증한 뒤 새 신청 테이블에 행을 생성한다. 직원 정보는 서버 측 Flow가 확인한다.
- 신청 조회·캘린더: 새 신청 테이블에서 자신의 신청과 승인 상태를 읽는다.
- 관리자 조회: 별도 관리자 인증 Flow가 `WeekendWork` 자격을 확인한 뒤 신청 상태와 반려 사유를 조회한다. 비밀번호 테이블을 앱에 직접 연결하지 않는다.
- 기존 화면과 제어 이름·반응형 레이아웃을 유지한다.

## 승인 경로

1. SharePoint 조직도 목록에서 신청자 `UserEmail`의 `팀원` 또는 `Leader` 행을 찾아 팀을 정하고, 해당 팀 `Leader`에게 1차 승인을 요청한다. 팀 리더 본인이 신청하면 1차를 본인이 승인한다.
2. `bs.seo@dexconsulting.net`에게 2차 승인을 요청한다. 해당 임원 본인의 신청은 1차를 생략하고 2차부터 시작하며, 2차 본인 승인을 허용한다.
3. `ms.park@dexconsulting.net`에게 3차 경영지원 확인을 요청한다. 해당 담당자 본인의 신청은 1차를 생략하고 2·3차를 진행하며, 3차 본인 확인을 허용한다.

각 단계의 거부는 다음 단계를 시작하지 않고 신청 행에 거부 결과·사유를 남기며 신청자에게 메일을 보낸다. 1차 매핑이 필요한 신청에서 조직도 매핑에 실패하면 승인을 보내지 않고 `RoutingError`로 남긴다. 위에 명시한 본인 승인 및 확인은 허용한다.

## 아직 필요한 연결 정보

- 시험 후 직원 배포 시 사용자별 신청 권한에 쓸 Dataverse 보안 역할과 배포 대상. 현재는 이승우 계정만 앱을 사용한다.
- 승인 Flow의 실제 실행 확인.

SharePoint 조직도 목록은 `Orgnization_Chart_Department_User_List`이며, 내부 열 `Title`과 문자 열 `UserEmail`을 Studio 스키마에서 확인했다. 승인 Flow는 **활성화**했지만 실제 신청·승인 실행은 아직 검증하지 않았다.

## 검증 기준

- 원본 행 수와 복제 행·업무 값·사진을 비교한다.
- 새 신청 테이블의 예정/완료 등록·조회·수정·삭제를 확인한다.
- 앱 제출 → 1·2·3차 승인 또는 중간 거부 → Dataverse 상태·신청자 메일을 확인한다.
- Canvas 컴파일과 게시본의 실제 실행을 별도로 확인한다.
